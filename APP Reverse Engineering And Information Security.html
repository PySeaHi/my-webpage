引言写在前面

APP 逆向工程是一项系统性的技术，涉及网络通信分析、代码逆向还原、安全防护绕过等多个方面。本文面向初中级信息安全人员与爬虫工程师，提供一份结构化的 APP 逆向工程技术详解：内容涵盖抓包技术、参数逆向分析方法，以及 APP 安全防护与逆向突破策略。

通过掌握这些技术，你可以更深入地理解 APP 的运行机制，发现潜在的安全漏洞，或在合法授权范围内实现特定的数据采集与分析目标。

在现代移动应用安全分析中，逆向工程技术不仅是理解应用行为的钥匙，更是发现安全漏洞、提升应用防护能力的重要工具。

1. APP 网络通信抓包技术Chapter 1

1.1 系统代理抓包与配置

在 APP 逆向工程中，抓包是分析网络通信行为、理解数据交互逻辑的关键第一步。系统代理抓包是最基础也最常用的方式：通过将移动设备（如 Android 手机）的网络流量导向 PC 端的抓包工具（Charles / Fiddler / Burp Suite / mitmproxy 等），实现对 HTTP/HTTPS 等应用层协议的监控与分析。 3 483

代理配置流程

  • 在 PC 端设置抓包工具监听特定端口
  • 移动设备 Wi-Fi 设置中配置代理服务器
  • 安装抓包工具的 CA 证书到设备
  • 验证 HTTPS 流量是否可正常捕获

常见代理检测绕过

  • 使用 iptables 强制流量转发（透明代理）
  • 修改 Smali 代码移除代理检测逻辑
  • 使用 Drony / Postern 等透明代理工具
  • ProxyDroid 全局代理模式
bash · iptables 
# 使用 iptables 将特定 APP 流量转发到透明代理
iptables -t nat -A OUTPUT -p tcp ! -d 127.0.0.1 \
  -m owner --uid-owner <APP_UID> --dport 0:65535 \
  -j DNAT --to-destination 127.0.0.1:<REDSOCKS_PORT>

1.2 客户端证书校验绕过方法

HTTPS 协议通过 SSL/TLS 加密通信内容，保证了数据传输的安全性。然而，从 Android 7.0（Nougat）开始，系统默认不再信任用户安装的 CA 证书，除非 APP 在 network_security_config.xml 中显式配置为信任用户证书。 105 140

Android 7+ 的默认证书策略是最常见的"抓包看不到 HTTPS 内容"的原因。首次尝试抓包却只有 CONNECT 请求时，优先排查这一点。
方法类别 具体方法 描述 适用场景
证书管理 将 CA 证书安装到系统信任区 Root 设备上将 CA 证书复制到 /system/etc/security/cacerts/ 并设置权限 需 Root，适用于 Android 7.0+
证书管理 修改 network_security_config.xml 添加 <trust-anchors> 标签，包含 <certificates src="user"/> 需反编译、重打包、重签名 APK
Hook 框架 使用 Xposed 模块 Hook APP 中负责证书校验的 API，使其直接返回验证成功 需安装 Xposed，主要针对 Java 层校验
Hook 框架 使用 Frida Hook 编写 Frida 脚本 Hook SSL/TLS 相关函数，强制信任所有证书 灵活，可应对 Java 层和部分 Native 层校验
环境配置 降低 Android 版本/特定模拟器 Android 7.0 以下系统默认信任用户证书 测试环境允许的情况下使用

1.3 服务端证书校验绕过技巧（SSL Pinning）

服务端证书校验，通常指 SSL Pinning（证书绑定）：APP 客户端不仅校验服务端证书是否由受信任 CA 签发，还会进一步校验服务端返回的证书公钥/证书指纹是否与 APP 内置的特定值完全一致。 106 144

当 APP 启用了 SSL Pinning 后，使用 Charles/Fiddler 抓包往往会出现 SSL handshake with client failed 错误，或 APP 直接报错"网络异常"，此时必须绕过 Pinning 才能看到明文。
实战首选方案：使用 Frida + objection，一行命令 android sslpinning disable 即可绕过绝大多数应用层 SSL Pinning，效率最高。

1.4 TCP 协议抓包与分析

虽然 HTTP/HTTPS 是最常见的协议，但许多对性能和实时性要求高的 APP（游戏、即时通讯、音视频流等），会直接使用 TCP/UDP 等底层协议传输数据，或基于其封装自定义应用层协议。 12

tcpdump 使用

bash 
# 在 Android 设备上执行
./tcpdump -i any -p -s 0 -w /sdcard/cap.pcap

# 参数说明
-i any   # 监听所有网络接口
-p       # 不启用混杂模式
-s 0     # 捕获完整数据包（65535）
-w       # 写入文件，后续可用 Wireshark 分析

Wireshark 过滤语法

filter 
# 基础过滤
tcp.port == 8888
ip.addr == 192.168.1.100 && tcp

# 高级过滤
tcp contains "keyword"
tcp.flags.syn == 1
tcp.analysis.retransmission

1.5 QUIC 协议抓包与挑战

QUIC（Quick UDP Internet Connections）是 Google 主导的基于 UDP 的传输协议，旨在减少连接建立延迟、改进拥塞控制并提供更强的安全性。QUIC 默认集成 TLS 1.3，在传输层就已加密，传统 TCP 抓包工具无法直接解析其内容。 15

QUIC 抓包技术方案

  • Wireshark 3.0+：配置 SSLKEYLOGFILE 环境变量导出密钥，支持 QUIC 解码
  • mitmproxy 10+：已支持 HTTPS/3（QUIC）中间人代理
  • 协议降级：通过 Frida Hook 强制应用走 HTTP/2 或 HTTP/1.1

2. APP 参数逆向分析方法Chapter 2

2.1 Java 层代码反编译与分析

Java/Kotlin 层是 Android APP 业务逻辑的主要载体，对其进行反编译分析是 APP 逆向的核心环节。常用 Java 反编译工具有 Jadx、JEB、Bytecode Viewer 等。 17 18

Jadx 功能特点

  • 提供 GUI 界面与命令行双版本
  • 跨平台支持 Windows / Linux / macOS
  • 反混淆、显示"坏代码"高亮提示
  • 强大的全局搜索（字符串/类名/方法名）
  • 直接解析 AndroidManifest.xml 与资源文件

JEB 高级功能

  • 支持多处理器架构的 Native 代码反编译
  • 处理混淆代码并支持手工重构分析
  • 重建资源与混淆后的 XML 文件
  • 支持 Dalvik 与 Native 代码无缝调试
  • 以太坊智能合约等扩展反编译支持

2.2 Native 层（C/C++）代码反编译与分析

Android APP 除 Java/Kotlin 代码外，还可包含 Native 代码（通常以 .so 共享库形式存在于 APK 的 lib/ 目录）。Native 代码常用于高性能计算、底层系统调用、复用 C/C++ 库，或承载核心加密算法与安全防护逻辑。

IDA Pro 分析流程

  1. 打开目标 .so 文件，IDA 自动完成初步分析
  2. 识别函数、字符串、导入表、导出表等符号信息
  3. 定位目标函数（JNI 方法或关键加密函数）
  4. 分析汇编代码，按 F5 查看伪代码（Hex-Rays）
  5. 使用交叉引用（Xrefs）和图形视图辅助调用链分析
通过分析伪代码的逻辑流程、变量赋值、函数调用，可推断出 Native 函数的功能和算法实现。动态调试（IDA + gdbserver/frida）是分析混淆/加壳 Native 代码的必要手段。

2.3 动态分析：Frida 的应用与实战

Frida 是一款强大的动态代码插桩（Dynamic Code Instrumentation）工具，支持 Android / iOS / Windows / macOS / Linux 多平台。它允许通过 JavaScript 脚本 Hook 函数调用、修改内存数据、调用任意函数，而无需修改原始 APP 代码。 31 370

javascript · frida 
// Frida 基本 Hook 示例
Java.perform(function () {
    var TargetClass = Java.use("com.example.TargetClass");

    TargetClass.targetMethod.implementation = function (param1, param2) {
        console.log("[*] Hook 成功，参数:", param1, param2);

        // 可修改参数、修改返回值，或在调用前后做自定义逻辑
        var result = this.targetMethod(param1 + " modified", param2);
        return result + " modified";
    };
});

  • Java.use(className) —— 获取 Java 类引用

Objection 自动化工具

  • android sslpinning disable —— 一键禁用 SSL Pinning
  • android root disable —— 绕过 Root 检测
  • android hooking watch —— 监控方法调用
  • 支持非 Root 设备通过 Frida Gadget 注入

2.4 动态分析：Xposed 框架的应用与绕过

Xposed 是运行于 Android 系统的经典动态 Hook 框架，通过替换 app_process 在 Zygote 阶段加载模块，允许在不修改 APK 的前提下改变系统和应用行为。与 Frida 相比，Xposed 专注于 Java 层 Hook，需要修改系统环境，但模块常驻、无需每次注入。 389

java · xposed 
public class MyModule implements IXposedHookLoadPackage {
    public void handleLoadPackage(LoadPackageParam lpparam) throws Throwable {
        if (!lpparam.packageName.equals("target.package")) return;

        XposedHelpers.findAndHookMethod("com.example.TargetClass",
            lpparam.classLoader, "targetMethod",
            String.class, int.class, new XC_MethodHook() {
                @Override
                protected void beforeHookedMethod(MethodHookParam param) {
                    // 方法执行前：可修改参数
                }
                @Override
                protected void afterHookedMethod(MethodHookParam param) {
                    // 方法执行后：可修改返回值
                }
            });
    }
}

3. APP 安全防护与逆向突破Chapter 3

3.1 APP 常见检测机制与绕过方法

Root 检测与绕过

Root 检测是 APP 常用的安全防护手段，用于识别运行环境是否具有 Root 权限。常见检测点包括：特定路径是否存在 su、系统属性 ro.build.tags、已安装应用列表、执行 su 命令、Build 指纹等。 201 208

检测点类别 具体检测方法 应用层 Hook 绕过 系统层 AOSP 定制
Root 文件检测 检查 /system/bin/su、/system/xbin/su 等路径 Hook 文件访问函数，返回 false 修改文件系统，移除或重命名 su
系统属性检测 检查 ro.build.tags 是否为 test-keys Hook SystemProperties.get() 修改 build.prop，改为 release-keys
Root 应用检测 检查是否安装 SuperSU/Magisk Manager 等包名 Hook 包管理器 API，过滤 Root 管理应用 卸载或冻结 Root 管理应用
Root 命令检测 尝试执行 su -c whoami Hook Runtime.exec() 修改 su 二进制，返回非 root 结果
系统指纹检测 检查 Build.FINGERPRINT/TAGS 字段 Hook android.os.Build 相关方法 修改 AOSP 中 deriveFingerprint()

3.2 APP 加壳（加固）技术与脱壳方法

APP 加壳（加固）是保护 Android 应用免受逆向与篡改的核心技术，思路是对原始 DEX（Java 代码）和 so（Native 代码）进行加密、混淆、虚拟化处理，运行时再由壳程序解密加载。 203 266

常见加壳技术

  • 整体加固（DEX 加密）：壳程序整体加密原始 DEX，运行时解密加载
  • 抽取壳：抽取方法体指令单独加密，原方法体用 NOP 填充
  • VMP 壳：代码转为自定义指令集字节码，内置解释器执行
  • so 加固：Native 库代码混淆、控制流平坦化、字符串加密

脱壳方法分类

  • 静态脱壳：分析壳解密算法，编写解密脚本
  • 动态脱壳：利用 APP 运行时内存中的数据
  • 内存 Dump：分析内存布局，提取解密后的 DEX/so
  • Hook 关键函数：Frida/Xposed Hook DEX 加载点
  • 定制 ROM/插桩脱壳：AOSP 源码中插入 Dump 代码

3.3 使用 Frida 进行动态脱壳

Frida 在动态脱壳方面具备独特优势。经典工具 FRIDA-DEXDump（hluwa 开源）是基于 Frida 的 Android 脱壳器，利用内存特征扫描自动 dump 出解密后的 DEX。 341 344

FRIDA-DEXDump 脱壳步骤

  1. 确保 Android 设备已 Root，并安装版本匹配的 frida-server
  2. PC 端安装：pip install frida-dexdump
  3. 启动目标 APP
  4. PC 执行：frida-dexdump -U -f com.target.app
  5. 工具自动附加进程，搜索并 dump 内存中的 DEX 文件
javascript · frida 脱壳 
// 自定义 Frida 脱壳脚本：扫描 DEX 魔数并 dump
Java.perform(function () {
    var dexDump = function () {
        Process.enumerateRanges('r--').forEach(function (range) {
            try {
                var magic = range.base.readCString(4);
                if (magic === 'dex\n') {
                    console.log('[+] Found DEX at:', range.base);

                    // DEX 头 0x20 处为 file_size（单位：uint，需注意对齐）
                    var fileSize = range.base.add(0x20).readUInt() * 4;
                    console.log('[+] DEX size:', fileSize);

                    var dexData = range.base.readByteArray(fileSize);
                    var outPath = '/sdcard/dex_dump_' + range.base + '.dex';
                    var outFile = new File(outPath, 'wb');
                    outFile.write(dexData);
                    outFile.close();
                    console.log('[+] Dumped to:', outPath);
                }
            } catch (e) { /* 忽略不可读区域 */ }
        });
    };

    // 延时执行，等待壳解密 DEX 并加载
    setTimeout(dexDump, 3000);
});

3.4 基于 AOSP 定制系统进行高级逆向

基于 AOSP（Android Open Source Project）定制系统是高级 APP 逆向的终极武器：通过修改并编译系统源码，可在系统层面对 APP 行为进行深度监控与干预。对复杂加固、强效检测、底层 Hook 等场景效果最佳。 266 270

AOSP 定制优势

  • 隐蔽性强：系统级修改难以被 APP 检测
  • 控制力强：可深度干预 APP 运行环境
  • 稳定性高：一次修改，长期有效
  • 功能强大：可同时脱壳+绕检测+抓包

FART 脱壳机原理

  • 修改 ART 虚拟机源码
  • 在类初始化/方法执行时插入 Dump 代码
  • 主动调用 DEX 中各个函数
  • 诱使壳解密对应 method 指令区
  • 自动 dump 内存 DEX 数据
定制 AOSP 进行逆向的优势在于强大控制力与隐蔽性，但技术门槛较高，需要熟悉 Android 系统架构、AOSP 源码结构与编译流程。建议在 Frida/Xposed 方案失效时再考虑。
