写在前面：逆向到底在逆什么？

很多同学一听到"逆向"就觉得高深，其实这个案例里的逆向，本质上就回答三个问题：

问题一

密码在提交前被做了什么处理？

AES-CBC-Pkcs7 加密

问题二

加密用的 key 从哪来？

页面隐藏字段 / JS变量

问题三

加密用的 iv 从哪来？

前端随机生成，随密文传输

只要把这三个问题答清楚，逆向就完成了。下面我们一步步来。

  2. 2 搜索关键词，按优先级尝试：

3.2 找到目标JS

通常会在某个 login.js、auth.js 或内联 script 中找到类似代码：

JavaScript - 加密核心函数 
// 加密
function encrypt(word) {
    var key = CryptoJS.enc.Utf8.parse($("#key").val());
    var ivOrg = randomString(16);
    var iv = CryptoJS.enc.Utf8.parse(ivOrg);

    var srcs = CryptoJS.enc.Utf8.parse(word);
    var encrypted = CryptoJS.AES.encrypt(srcs, key, {
        iv: iv,
        mode: CryptoJS.mode.CBC,
        padding: CryptoJS.pad.Pkcs7
    });
    // encrypted是已经被base64的，先解密，然后在拼接
    var res = iv.concat(CryptoJS.enc.Base64.parse(encrypted.toString()));
    return CryptoJS.enc.Base64.stringify(res);
}

function randomString(length, chars) {
    var chars = '0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ';
    var result = '';
    for (var i = length; i > 0; --i)
        result += chars[Math.floor(Math.random() * chars.length)];
    return result;
}

3.3 从代码里读出关键信息

代码 含义 逆向结论
CryptoJS.enc.Utf8.parse($("#key").val()) key 从页面 #key 元素取值 key 在 DOM 里！
var ivOrg = randomString(16) iv 是随机生成的 iv 每次都不一样！
CryptoJS.mode.CBC CBC 模式 模式确定
CryptoJS.pad.Pkcs7 Pkcs7 填充 填充确定
iv.concat(Base64.parse(encrypted)) IV 拼在密文前面 密文 = IV ‖ ciphertext
Base64.stringify(res) 整体再 Base64 输出格式确定

至此，加密逻辑已经完全清楚了。接下来分别去拿 key 和 iv。

var key = CryptoJS.enc.Utf8.parse($("#key").val());

$("#key") 是 jQuery 选择器，意思是：找 id 为 key 的元素，取它的 value。

4.4 逆向结论：key 的获取方式

重要提醒

key 不是写死的，是服务端渲染进页面的。因此不要把它硬编码在 Python 里（服务端一换就全挂），应该跟 lt 一起，在 GET /auth/login 的响应里用 XPath 提取。

Python - 提取lt和key 
def get_it_and_key(session):
    url = "/auth/login"
    params = {'service': 'YUhSMGNITTZMeTluZFdsa1pTNXRaV1JzYVhabExtTnU=/cas/dir'}
    response = session.get(url=url, params=params)
    tree = etree.HTML(response.text)

    # 提取 lt
    lt = tree.xpath("//input[@type='hidden' and @name='lt']/@value")

    # 提取 key（按实际 DOM 结构调整 XPath）
    key = tree.xpath("//input[@type='hidden' and @id='key']/@value")

    print(f"lt = {lt}, key = {key}")
    return lt, key

问题来了：iv 是 randomString(16) 现场生成的，页面里没有，DOM 里也没有，那服务端怎么知道 iv 是多少？

5.2 看下一行代码，答案揭晓

var res = iv.concat(CryptoJS.enc.Base64.parse(encrypted.toString()));
return CryptoJS.enc.Base64.stringify(res);

最终提交的 password 字段结构：

16字节 IV
随机生成
AES-CBC 密文
Pkcs7填充
↑ 整体 Base64 编码 ↑

核心结论

这就是为什么 IV 不需要额外传给服务端——它直接拼在密文里了。服务端收到后：Base64解码 → 取前16字节作为IV → 取剩余部分作为密文 → 用key+IV解密。

5.5 Python端怎么复刻

在 Python 里，IV 由我们自己随机生成，然后同样拼到密文前面：

Python - 密码加密函数 
import random
import string
import base64
from Crypto.Cipher import AES
from Crypto.Util.Padding import pad

# 前端 randomString 的字符集
IV_CHARS = string.digits + string.ascii_letters  # 0123456789a-zA-Z

def random_iv(length=16):
    """复刻前端的 randomString(16)"""
    return ''.join(random.choices(IV_CHARS, k=length))

def encrypt_password(password, key):
    # 1. 生成随机 IV
    iv_org = random_iv(16)
    iv = iv_org.encode('utf-8')       # 字符集全是 ASCII，16字符 = 16字节
    key_bytes = key.encode('utf-8')

    # 2. AES-CBC-Pkcs7 加密
    cipher = AES.new(key_bytes, AES.MODE_CBC, iv=iv)
    ciphertext = cipher.encrypt(pad(password.encode('utf-8'), AES.block_size))

    # 3. IV 前置拼接 + Base64
    combined = iv + ciphertext
    return base64.b64encode(combined).decode('utf-8')

# 使用
pwd_aes = encrypt_password("your_password", "GVJD5Ola4s3VfeTc")
print(pwd_aes)

关键教学点：怎么证明你的逆向是对的？

使用固定IV对比法：两端使用相同的key、IV、明文，输出必须完全一致。

key = b"GVJD5Ola4s3VfeTc"

两者的输出必须一模一样。如果不一样，按右侧顺序排查：

IV是否一致
3

4

5
IV前置拼接

隐患1：IV被固定，未随机

原代码配置中写死IV，与真实浏览器行为不一致，容易被风控识别。

iv: "5K4MtyzlwzEBDVrD"
iv = random_iv(16).encode('utf-8')

隐患2：Key硬编码

key是服务端渲染的，硬编码一旦服务端轮换就全挂。必须动态从页面提取。

key = "GVJD5Ola4s3VfeTc" #硬编码
key = tree.xpath(".../@value")

完整调用示例（修正版）

Python - 完整登录流程 
import random
import string
import requests
from lxml import etree
from Crypto.Cipher import AES
from Crypto.Util.Padding import pad
import base64

IV_CHARS = string.digits + string.ascii_letters

def random_iv(length=16):
    return ''.join(random.choices(IV_CHARS, k=length))

class AESManager:
    def __init__(self, key: bytes, iv: bytes):
        self.iv = iv
        self.cipher = AES.new(key, AES.MODE_CBC, iv=iv)

    def encrypt(self, plaintext: str) -> str:
        srcs = plaintext.encode('utf-8')
        encrypted = self.cipher.encrypt(pad(srcs, AES.block_size))
        combined = self.iv + encrypted          # IV前置拼接
        result = base64.b64encode(combined).decode('utf-8')
        return result

def get_it_and_key(session):
    url = "/auth/login"
    params = {'service': 'YUhSMGNITTZMeTluZFdsa1pTNXRaV1JzYVhabExtTnU=/cas/dir'}
    response = session.get(url=url, params=params)
    tree = etree.HTML(response.text)

    lt = tree.xpath("//input[@type='hidden' and @name='lt']/@value")
    key = tree.xpath("//input[@type='hidden' and @id='key']/@value")
    return lt[0] if lt else None, key[0] if key else None

def login(session, lt, username, pwd_aes):
    # 提交登录表单逻辑
    # ...
    return True

def get_token(session):
    # 获取_token逻辑
    # ...
    return "xxx"

def run(username, password):
    session = requests.Session()

    # 1. 从页面拿 lt 和 key（动态获取，不硬编码）
    lt, key = get_it_and_key(session)

    # 2. 随机 IV + AES 加密（每次IV不同，更接近真实浏览器）
    iv = random_iv(16).encode('utf-8')
    aes_cry = AESManager(key.encode('utf-8'), iv)
    pwd_aes = aes_cry.encrypt(password)

    # 3. 登录
    if not login(session, lt, username, pwd_aes):
        return None, None

    # 4. 获取 _token
    token = get_token(session)
    return session, token

if __name__ == "__main__":
    session, token = run("your_username", "your_password")
    print("登录成功, token:", token)

逆向要点总结

1

逆向不是猜，是从现象倒推实现

先抓包看到密文，再搜encrypt找到加密函数。

2

key 在 DOM 里

前端代码$("#key").val()直接暴露了key的位置。

3

iv 在密文里

前端随机生成IV后拼接到密文前，整体Base64。

4

AES 四要素

key（页面动态）、IV（随机16字节）、mode=CBC、padding=Pkcs7。

5

输出格式是最大坑点

不是Base64(ciphertext)，而是Base64(IV_bytes ‖ ciphertext_bytes)。

6

验证方法

固定IV，前端JS和Python各跑一遍，输出必须相同。

7

落地要点

key动态获取、IV每次随机，才能长期稳定不被风控。

8

Session一致性

获取lt、提交登录、获取_token必须同一session。
