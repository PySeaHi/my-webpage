密钥处理逻辑
  • • 原始密钥字符串长度必须为22位
  • • 末尾补两个 "==" 凑齐Base64填充
  • • Base64解码后得到 16字节 原始密钥
IV向量规律
  • • IV不需要额外寻找！
  • • 直接使用解码后密钥的前16字节
  • • 加密模式为 AES/CBC/PKCS5Padding
常见踩坑点

很多人看到密钥只有22位会疑惑，以为密钥错误。实际上22字符Base64解码后正好是16字节（ceil(16*4/3)=22），补"=="是因为Base64解码要求输入长度是4的倍数。

Java → Python 算法复现

使用pycryptodome库实现等价的解密逻辑

根据分析出的逻辑，可以轻松用Python实现等价的解密函数。核心逻辑和Java代码一一对应：

Python · 完整解密实现 
"""
某mai通用药参考 APP 接口响应解密
还原 getListDrugCateLastPreparation Java 逻辑
"""
import base64
import json
import requests
from Crypto.Cipher import AES
from Crypto.Util.Padding import unpad

# AES 密钥：Java中 "bnpxN3EwRmg0N09kcFhzRQ" + "==" 后 Base64 解码
_KEY = base64.b64decode("bnpxN3EwRmg0N09kcFhzRQ==")  # 16 bytes
_IV = _KEY[:16]  # IV取密钥前16字节

def aes_decrypt(ciphertext: str) -> dict | None:
    """AES/CBC 解密，对应 Java 的 x1.b.a(str, 'bnpxN3EwRmg0N09kcFhzRQ')"""
    try:
        raw = base64.b64decode(ciphertext)
        cipher = AES.new(_KEY, AES.MODE_CBC, _IV)
        plain = unpad(cipher.decrypt(raw), AES.block_size)
        return json.loads(plain.decode("utf-8"))
    except Exception as e:
        print(f"解密失败: {e}")
        return None


if __name__ == "__main__":
    # 替换为抓包得到的密文
    ciphertext = 'uAMdR6P5VEOav63MMbDM2ckVV5+q4NdgVZP8O8Tqt+68fNrEGHRfXduXapw8+lne...'
    result = aes_decrypt(ciphertext)
    print(json.dumps(result, ensure_ascii=False, indent=2))

核心要点总结

逆向思路

APP能显示明文就一定有解密逻辑，不要尝试暴力破解密钥，沿着数据处理链路追踪是最高效的方式。

密钥特征

22位字符串+补"=="是Base64编码16字节密钥的典型特征，不要因为长度不是16/24/32就误判不是AES密钥。

IV的规律

很多简单的APP实现中，IV不会单独生成或传输，经常直接使用密钥前16位或固定字符串，不要盲目寻找。

跨语言复现

Java和Python的加密库参数对应关系：AES/CBC/PKCS5Padding 等价于 AES.MODE_CBC + unpad(PKCS7)。
